# البنية المعمارية والتصميم الداخلي لمكتبة Bifrost

يوثق هذا الملف الهيكلية منخفضة المستوى للذاكرة المشتركة، والآليات الذرية، وتقنيات تحسين الأداء التي تمنح Bifrost زمن استجابة دون الميكروثانية ومعدلات نقل فائقة السرعة.

---

## 🧠 تخطيط الذاكرة منخفض المستوى (Memory Layout)

يتم تعيين مجمع الذاكرة المشتركة (`/dev/shm/bifrost_<name>`) ككتلة متصلة واحدة داخل فضاء العناوين الافتراضية لكل عملية مشاركة. داخلياً، تُخزن كافة المؤشرات كـ **إزاحات نسبية (Relative Offsets)** من بداية المجمع، مما يجعل المجمع قابلاً للنقل والعمل بكفاءة حتى لو تم تعيينه في عناوين افتراضية مختلفة لدى العمليات المتعددة.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. ترويسة المجمع (محاذاة لسطر الكاش 64 بايت)                 │
│    - الرقم السحري ('BFR1')، رقم الإصدار، وحجم الترويسة       │
│    - عدادات وإحصائيات ذرية عالمية (عمليات القراءة والكتابة)  │
│    - إزاحة ساحة البيانات، وإزاحة منطقة الأوامر               │
├─────────────────────────────────────────────────────────────┤
│ 2. دليل المشاركين والخانات (Participant Directory)          │
│    - مصفوفة ثابتة لخانات المشاركين (max_participants)        │
│    - آلة حالات الخانات: فارغة -> قيد الكتابة -> جاهزة للقراءة│
│    - عدادات أجيال ABA (تزداد ذرياً مع كل إعادة تدوير للخانة) │
│    - عدادات الإصدار التسلسلي للبيانات                        │
├─────────────────────────────────────────────────────────────┤
│ 3. ساحة البيانات (مخصص الدفع بالبايت Bump Allocator)        │
│    - مساحة ذاكرة متصلة لحفظ البيانات المنشورة                │
│    - حجز ذري بدون أقفال باستخدام (fetch_add)                 │
├─────────────────────────────────────────────────────────────┤
│ 4. منطقة الأوامر والتحكم (صناديق طوابير RPC)                │
│    - صناديق طلبات الكتاب: طوابير حلقية MPSC محصورة وبلا أقفال│
│    - صناديق ردود القراء: طوابير دائرية مخصصة للردود الذرية   │
│    - كلمات Futex للإشعار الخفيف وتوفير استهلاك المعالج       │
└─────────────────────────────────────────────────────────────┘
```

## ⚡ التزامن والترتيب الذري للذاكرة (Memory Ordering)

لا تستخدم Bifrost أقفال نظام التشغيل الثقيلة (مثل POSIX Mutexes) في مسارات نقل البيانات الساخنة.

### 1. نشر البيانات (Release Semantics)
عندما يقوم الكاتب بنشر بيانات جديدة:
```c
// 1. تعديل البيانات مباشرة في المؤشر المحجوز مسبقاً
slot->data_ptr[i] = value;

// 2. حاجز ذاكرة عتادي يضمن كتابة التعديلات قبل تحديث حالة الخانة
atomic_thread_fence(memory_order_release);

// 3. تخزين ذري يحدد الحالة كـ READY ويزيد رقم الإصدار
atomic_store_explicit(&slot->version, new_ver, memory_order_release);
atomic_store_explicit(&slot->state, BIFROST_SLOT_READY, memory_order_release);
```

### 2. قراءة البيانات (Acquire Semantics)
عندما يقرأ القارئ البيانات:
```c
// 1. تحميل ذري بنمط Acquire يمنع المعالج من قراءة البيانات قبل التأكد من جاهزيتها
if (atomic_load_explicit(&slot->state, memory_order_acquire) == BIFROST_SLOT_READY) {
    uint64_t v = atomic_load_explicit(&slot->version, memory_order_acquire);
    // 2. الوصول المباشر للمؤشر دون أي نسخ في الذاكرة
    consume(slot->data_ptr);
}
```

### 3. الحماية ضد معضلة ABA عبر عدادات الأجيال
إذا تعطلت عملية كاتب بصورة مفاجئة وانضمت عملية أخرى وشغلت نفس الخانة، قد يقوم قارئ بإرسال طلب قديم يصل بالخطأ للعملية الجديدة. تعالج Bifrost ذلك من خلال بنية `bifrost_writer_ref_t` التي تدمج معرف الخانة مع عداد جيل يتزايد ذرياً:
```c
typedef struct {
    uint32_t id;    // رقم خانة المشارك
    uint32_t gen;   // عداد جيل الخانة
} bifrost_writer_ref_t;
```
إذا لم يتطابق رقم الجيل في الطلب مع جيل الخانة الحالي، يُرفض الطلب فوراً برمز `BIFROST_ERR_NOTFOUND`.

### 4. وضع الدوران النشط (Spinning) مقابل سكون Futex
*   **الدوران السريع (Spinning)**: للأنظمة فائقة السرعة التي تتطلب زمناً أقل من ميكروثانية، يدور المسلك في حلقة خفيفة لاستقبال التحديث فوراً.
*   **سكون Futex**: توفر دوال مثل `bifrost_writer_wait_command()` دوراناً وجيزاً يتبعه نداء لنظام التشغيل `SYS_futex` لوضع المسلك في حالة سكون موفرة للطاقة حتى وصول طلب جديد.

## 🚀 قائمة إرشادات التحسين للأداء الفائق

### 1. تجنب تكرار الحجز في الحلقات السريعة
*   **خطأ شائع**: استدعاء `bifrost_writer_alloc()` في كل إطار (60 إطار في الثانية مثلاً).
*   **الممارسة المثلى**: حجز الهيكل مرة واحدة عند الإقلاع، ثم التعديل مباشرة على حقول المؤشر واستدعاء `bifrost_writer_publish()`.

### 2. تسريع القراءة بالمعرف الرقمي (Fast ID Lookups)
*   **خطأ شائع**: استدعاء `bifrost_reader_get(reader, "writer_name", &size)` مع كل فحص، مما يستهلك وقتاً في مقارنة النصوص.
*   **الممارسة المثلى**: جلب المعرف الرقمي للكاتب عبر `bifrost_reader_find_writer()` مرة واحدة، ثم استخدام `bifrost_reader_get_by_id()` للقراءة المباشرة $O(1)$.

### 3. تثبيت المسالك على الأنوية (Core Pinning) وعزل النظام
للحصول على زمن استجابة ثابت دون تذبذب:
1. اعزل أنوية محددة من مجدول لينكس عبر معلمات النواة: `isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3`.
2. ثبت مسلك الكاتب على النواة 2 (`pthread_setaffinity_np`).
3. ثبت مسلك القارئ على النواة 3.
4. اضبط نمط طاقة المعالج على الأداء الأقصى (`performance`).

### 4. الصفحات الضخمة (Huge Pages)
لتدفقات الفيديو والصور الضخمة (مثل 4K أو 8K):
استخدم ذاكرة مشتركة مدعومة بـ HugeTLB لتقليل إخفاقات TLB في الذاكرة والحفاظ على أعلى سرعة معالجة.
